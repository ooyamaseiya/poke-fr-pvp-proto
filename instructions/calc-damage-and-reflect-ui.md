# 指示書：Step 2-3b ダメージ計算とHPバー更新の実装

あなたはレトロゲーム（ゲームボーイカラー・ポケットモンスター金銀世代）のフロントエンドエンジニアです。
Step 2-3aで実装した「先攻・後攻の決定」に続けて、**先攻から順番に全体攻撃のダメージ計算を行い、相手3体のHPバーとHP数値をリアルタイムに更新する仕組み**を `BattleScreen.jsx` / `BattleScreen.css` に実装してください。

※重要（スコープ制限）：
今回は**「ダメージ計算・HPバー更新・戦闘不能判定（後攻キャンセル含む）」のみ**を実装します。
以下の要素は**まだ実装しないでください**（以降のステップで追加します）：

- クールタイム（おやすみ状態 `💤`）
- 控え（残り3体）からの交代処理
- 6ターン制限・勝敗判定・リザルト画面
- 斬撃エフェクト、立ち絵の点滅・揺れ、タイプライター文字送り

## 1. フィールド上のHP状態（State）管理

Part 1から受け取った `p1Team` / `p2Team` の先頭3体（`slice(0, 3)`）を、バトル中にHPを更新できるState（`p1Field`, `p2Field`）として初期化してください。

```javascript
// フィールド上の1体あたりのデータ構造
{
  ...pokemonData,           // id, name, maxHp, atk, def, spd, moveName, sprites 等
  currentHp: pokemonData.maxHp,
  isFainted: false          // currentHp が 0 になったら true
}
```

## 2. ダメージ計算ロジック（純粋関数として切り出す）

以下の計算式で、攻撃側1体から防御側1体へのダメージを計算する関数 `calculateDamage(attacker, defender)` を作成してください。

```javascript
export function calculateDamage(attacker, defender) {
  const base = Math.floor(attacker.atk * 0.65 - defender.def * 0.25);
  const variance = 0.9 + Math.random() * 0.2; // 0.9〜1.1倍の乱数
  return Math.max(15, Math.floor(base * variance)); // 最低保証 15 ダメージ
}
```

- **全体攻撃の適用ルール：**
  - 攻撃は、相手フィールドにいる**生存ポケモン（`!isFainted`）全員**に対してそれぞれ `calculateDamage` を実行し、`currentHp` を減算する（下限は `0`）。
  - `currentHp` が `0` になった個体は `isFainted: true` に更新する。

## 3. 攻撃実行フロー（フェーズ遷移）

Step 2-3aの先攻・後攻決定フェーズから、以下の流れで攻撃とHP更新を実行してください。
※非同期処理（`async/await` ＋ 約 `1200ms` のウェイト関数）で自動進行させるか、または「つぎへ」ボタンで1段階ずつ進められるようにしてください（自動進行推奨）。

1. **先攻・後攻の表示（`SPEED_RESULT`）：**
   - Step 2-3aの判定メッセージを表示（約 `1200ms` 待機）。
2. **先攻の攻撃実行（`EXEC_FIRST`）：**
   - メッセージ：`[先攻プレイヤー] の [先攻ポケモン名] の [技名]！`（約 `1000ms` 待機）
   - 相手フィールドの生存ポケモン全員にダメージを適用し、Stateを更新する（HPバーが減る）。
   - メッセージ：`あいての ポケモンたちに ダメージ！`（約 `1200ms` 待機）
3. **後攻の攻撃実行（`EXEC_SECOND`）：**
   - **戦闘不能チェック（重要）：** 先攻の攻撃で、後攻が選んだ攻撃役がすでに `isFainted === true`（`currentHp <= 0`）になっていないか、最新のHP状態で判定する。
   - **倒れている場合（キャンセル）：**
     - メッセージ：`[後攻ポケモン名] は たおれて こうげきできない！`（約 `1200ms` 待機）
     - ダメージ処理はスキップする。
   - **生きている場合：**
     - 先攻と同様に技名メッセージ → 相手フィールドの生存ポケモン全員にダメージ適用 → ダメージメッセージ（ウェイト）。
4. **ターン終了・次の選択へ：**
   - `p1SelectedIndex`, `p2SelectedIndex`, `turnOrder` を `null` にリセットする。
   - もしどちらかの先発3体が全員 `isFainted` になっていれば、`turnPhase` を `'TEST_END'` にして `せんぱつ 3たいが ぜんめつした！ リセットしてね` と表示する。
   - そうでなければ `turnPhase` を `'SELECT_P1'` に戻し、次の選択を行えるようにする。

## 4. UI連動要件（HPバー・ひんし表示）

- **HPバーのアニメーションと色変化：**
  - HPバーの要素に `transition: width 0.5s linear;` を設定し、ダメージ時にバーが滑らかに減るようにする。
  - 残りHP割合（`currentHp / maxHp`）に応じて背景色を動的に切り替える：
    - `50%超`：緑（`#30B830`）
    - `21%〜50%`：黄（`#F8C028`）
    - `20%以下`：赤（`#E83030`）
  - P1側のステータス枠に表示している数値（例：`180/180`）も `currentHp` と連動して更新する。
- **戦闘不能（`isFainted: true`）の見た目と操作制限：**
  - バトルフィールド上の立ち絵をグレースケール＋半透明（`opacity: 0.3; filter: grayscale(100%);`）にする。
  - `SELECT_P1` / `SELECT_P2` の選択パネルにおいて、`isFainted: true` のポケモンボタンは `disabled`（選択不可）にし、`ひんし` ラベルを表示する。
- **テスト用リセットボタン：**
  - ヘッダーまたはテスト終了時に、全員のHPを全回復して最初からやり直せる「HPリセット」ボタンを用意しておくと動作確認がしやすい。

## 5. 実行・確認手順

1. `src/BattleScreen.jsx` および `src/BattleScreen.css` を更新する。
2. ビルド・起動し、以下の動作をすべて確認して完了報告を行うこと。
   - 先攻の攻撃で相手3体のHPバーが滑らかに減り、50%以下で黄色、20%以下で赤色に変わること。
   - P1側のHP数値表示がダメージに合わせて正しく減ること。
   - 先攻の攻撃で後攻の選択ポケモンがHP 0になった場合、後攻の攻撃がキャンセルされること。
   - HPが0になったポケモンがグレースケール表示になり、次のターンで選択できなくなること。
