# 指示書：Step 2-4b 6ターン制限・倒した数スコア・勝敗判定＆リザルト画面の実装

あなたはレトロゲーム（ゲームボーイカラー・ポケットモンスター金銀世代）のフロントエンドエンジニアです。
Step 2-4a-3までに完成した「6体フルバトル（先発3体＋控え3体の交代）」に、**最大6ターン制のターン管理・倒した数（KO）スコア表示・勝敗判定ロジック・リザルト画面**を組み込んで、1試合を最後まで遊べる状態にしてください。

## 0. 最重要ルール（スコープ厳守）

既存のバトル動作を壊さず確実に完了させるため、以下のルールを厳守してください。

- **変更対象ファイル：** `BattleScreen.jsx`（または `.tsx`）と、必要最小限のスタイル追記のみ `BattleScreen.css` を編集してください。`App.jsx` や `BenchSelectModal` は**編集禁止**です。
- **既存ロジックの維持：** ブラインド選択・すばやさ判定・ダメージ計算・2ターン疲労（`💦`）・P1/P2控え交代ロジックは書き直さないでください。
- **未実装機能の禁止：** 斬撃エフェクト再生、立ち絵の点滅・揺れ、タイプライター文字送りは**次のステップ（Step 2-5）**で実装します。今回は実装しないでください。

## 1. 倒した数（KOスコア）と残りHP合計の算出ルール

二重カウントやリセット漏れを防ぐため、スコアを別Stateで手動加算するのではなく、**現在のフィールドと控えの状態から算出する純粋関数（Derived State）**として実装してください。

- **初期チーム総数：** `p1Total = (p1Team || []).length`（通常6）、`p2Total = (p2Team || []).length`（通常6）
- **生存ポケモン総数の算出：**
  - `countAlive(field, bench)` ＝ `field.filter(p => !p.isFainted).length + bench.length`
- **倒した数（KOスコア）の算出：**
  - `p1KoCount = p2Total - countAlive(p2Field, p2Bench)`（P1が倒した相手の数）
  - `p2KoCount = p1Total - countAlive(p1Field, p1Bench)`（P2が倒した相手の数）
- **残りHP合計の算出（同点時の判定用）：**
  - `calcTotalRemainingHp(field, bench)` ＝
    `field` の生存ポケモンの `currentHp` 合計 ＋ `bench` の全ポケモンの `maxHp` 合計
- **ヘッダー表示の連動：**
  - 画面上部のヘッダーに、現在のターン数 `TURN {turn}/6` とスコア `P1 {p1KoCount} - {p2KoCount} P2` をリアルタイム表示すること。

## 2. バトル終了判定と6ターン制限の組み込み

以下の定数とStateを使用します。

- `MAX_TURNS = 6`
- `turn`（初期値 `1`）
- `turnPhase` に `'RESULT'` を追加する
- `battleResult`（初期値 `null`）：勝敗判定の結果オブジェクトを保持する

### 終了判定を実行するタイミング（重要）

先攻・後攻の攻撃処理および疲労ターン更新が終わった直後、**交代チェック（`REPLACE_P1` / `REPLACE_P2`）に入る前**に、まず以下の終了条件をチェックしてください。

1. **全滅チェック：**
   - `countAlive(updatedP1Field, p1Bench) === 0` または `countAlive(updatedP2Field, p2Bench) === 0` の場合：
   - 交代モーダルには入らず、直ちに勝敗判定を実行して `turnPhase` を `'RESULT'` へ遷移する。
2. **最終ターン（6ターン目）終了チェック：**
   - `turn >= MAX_TURNS`（6ターン目の攻撃が終了した）場合：
   - もう次のターンはないため、**交代モーダルには入らず**、直ちに勝敗判定を実行して `turnPhase` を `'RESULT'` へ遷移する。
3. **バトル継続の場合（1〜5ターン目 かつ 双方に生存あり）：**
   - これまで通り「P1交代チェック → P2交代チェック」へ進む。
   - すべての交代が完了して次のターン（`'SELECT_P1'`）へ戻るタイミングで、`setTurn(prev => prev + 1)` を実行する。
   - ※既存のテスト用終了フェーズ（`'TEST_END'` 等）があれば、この `'RESULT'` 遷移に統合して整理すること。

## 3. 勝敗判定ロジック（純粋関数 `judgeBattleResult`）

最新の `p1Field`, `p1Bench`, `p2Field`, `p2Bench` を受け取り、以下の優先順位で勝敗を決定する関数を作成してください。

1. **第1基準：倒した数（`p1KoCount` vs `p2KoCount`）**
   - 多い方の勝ち（`winner: 'P1'` または `'P2'`）。
   - 理由テキスト：全滅なら `6たい ぜんめつで しょうり！`、それ以外は `たおした かずで しょうり！`。
2. **第2基準（同点時）：残りHP合計（`p1TotalHp` vs `p2TotalHp`）**
   - 多い方の勝ち（`winner: 'P1'` または `'P2'`）。
   - 理由テキスト：`のこりHP ごうけいで はんていがち！`。
3. **第3基準（完全同点時）：引き分け**
   - `winner: 'DRAW'`。
   - 理由テキスト：`たおした かずも HPも おなじ！`。

```javascript
// 戻り値オブジェクトの例
{
  winner: 'P1', // 'P1' | 'P2' | 'DRAW'
  reason: 'たおした かずで しょうり！',
  p1Ko: 3,
  p2Ko: 2,
  p1RemainingHp: 420,
  p2RemainingHp: 310
}
```

## 4. リザルト画面（`turnPhase === 'RESULT'`）のUI要件

既存の目隠し画面オーバーレイと同じ金銀風の二重黒枠ウィンドウを流用し、画面中央に表示してください。

- **勝敗見出し：**
  - `P1` 勝利：`P1 の かち！`（P1カラー青 `#2860D8` をアクセントに使用）
  - `P2` 勝利：`P2 の かち！`（P2カラー赤 `#D82828` をアクセントに使用）
  - 引き分け：`ひきわけ！`
- **判定理由：** `battleResult.reason` をサブテキストとして表示。
- **スコア詳細ボックス（金銀風の内枠）：**
  - `たおした かず`：`P1 {p1Ko}たい  vs  {p2Ko}たい P2`
  - `のこりHP ごうけい`：`P1 {p1RemainingHp}  vs  {p2RemainingHp} P2`
- **アクションボタン（2つ並べて配置）：**
  1. **`おなじ チームで もういちど`**：
     - フィールド・控え・ターン数（`1`）・選択状態・`battleResult`（`null`）をすべて初期状態にリセットし、`turnPhase` を `'SELECT_P1'` に戻す。
  2. **`タイトルへ もどる`**：
     - ヘッダーの「もどる」ボタンと同じコールバック（親から渡されている `onBack` / `onReturnTitle` 等）を呼び出す。

## 5. 実行・確認手順

1. `BattleScreen.jsx`（および必要に応じて `BattleScreen.css`）を最小限の差分で更新する。
2. ビルド・起動し、以下の5点をすべて確認して完了報告を行うこと。
   - ポケモンが倒れるたびに、ヘッダーの `P1 X - Y P2` スコアが正確に増えること。
   - ターンが進むごとにヘッダーの `TURN 1/6` 〜 `TURN 6/6` が正しくカウントアップされること。
   - 6ターン目の攻撃終了時、交代モーダルに入らずリザルト画面が表示され、倒した数（同点なら残りHP合計）で正しく勝敗が判定されること。
   - 6ターン未満でもどちらかの6体が全滅した時点で即座にリザルト画面へ遷移すること。
   - リザルト画面の「おなじ チームで もういちど」で完全にTurn 1から再戦でき、「タイトルへ もどる」でタイトル画面へ戻れること。
