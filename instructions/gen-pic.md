# 指示書：ポケモンGOスクショからのドット絵自動生成パイプライン（改訂版）

あなたはレトロゲーム（ゲームボーイカラー〜ゲームボーイアドバンス世代）のドット絵テクニカルアーティスト兼Pythonエンジニアです。
人間が用意したポケモンGOの図鑑スクリーンショット画像を加工し、スマホ向けWeb PvPバトルゲーム用の**高精細ドット絵スプライト（正面・背面）**をPNG形式で生成してください。

※注意：SVG形式での出力は禁止します。すべてPythonスクリプトを実行してPNG画像として生成・保存してください。また、今回は立ち絵スプライトの生成のみを行い、技エフェクトの生成は不要です。

## 1. 入力フォルダとファイル命名規則

プロジェクトルートに `./raw_screenshots/` フォルダがあり、以下の規則でスクショが格納されています。

- ファイル名形式：`{ID}_{ポケモン名}_{front|back}.png`（拡張子は `.PNG` / `.jpg` / `.jpeg` の大文字・小文字すべてに対応すること）
  - 例：`0483_ディアルガ_front.png`、`0483_ディアルガ_back.png`

## 2. 立ち絵変換パイプライン（Python実装要件）

必要なライブラリ（`rembg`, `onnxruntime`, `pillow`, `numpy`, `scipy`）が未インストールの場合は先にインストールし、以下の手順で画像を一括変換するスクリプト（`build_sprites.py`）を作成・実行してください。

1. **UI除去（図鑑画面専用の厳密クロップ）：**
   ポケモンGOの図鑑スクショから、上部のステータスバーと下部の「ポケモン名・フォルムアイコン・タイプアイコン」を完全に除外するため、画像サイズ `(w, h)` に対して以下の比率（4点座標）で切り抜くこと。
   - `left = int(w * 0.05)`
   - `top = int(h * 0.06)`
   - `right = int(w * 0.95)`
   - `bottom = int(h * 0.38)`
2. **背景透過（切り抜き）：**
   クロップ後の画像に対して `rembg` を使用し、背景を完全に除去してポケモン本体のみを抽出する。
3. **トリミングと正方形化：**
   不透明ピクセル（Alpha > 128）のバウンディングボックスを検出し、余白を切り詰める。
   - `front`（正面）：正方形キャンバスの中央に配置（下端に2pxの余白）。
   - `back`（背面）：正方形キャンバスの下辺に接地させて配置（バストアップ構図を再現）。
4. **ドット絵化（72 × 72 px・高精細レトロ仕様）：**
   - `Image.Resampling.LANCZOS` を使用して特徴（角・トゲ・模様のライン）の欠落を防ぎつつ **`72 × 72 ピクセル`** にリサイズする。
   - **アルファチャンネルの二値化：** 半透明のフチをなくすため、Alpha >= 128 は `255`、128未満は `0` に変換する。
   - **減色処理：** RGB部分をディザリングなし（`Dither.NONE`）で**最大8色**に減色し、ディテールと陰影を残す。
   - **輪郭線の強調：** 透明ピクセルに隣接する不透明ピクセル（外周1px）を濃紺〜黒（`#14141E`）に置き換え、くっきりしたドット絵の輪郭線を作る。
5. **保存先：** `./output/assets/{ID}_{front|back}.png`

## 3. マニフェスト出力

すべてのPNG生成完了後、Reactアプリから読み込むための `./output/manifest.json` を以下の形式で出力してください。

```json
{
  "sprite_size": 72,
  "pokemons": [
    {
      "id": "0483",
      "name": "ディアルガ",
      "sprites": {
        "front": "./assets/0483_front.png",
        "back": "./assets/0483_back.png"
      }
    }
  ]
}
```

## 4. 実行順序

1. `build_sprites.py` を新規作成（または最新仕様で上書き）する。
2. `./raw_screenshots/` 内の最初の1体（front / back）だけ変換を実行し、画像サイズや色数が仕様通りかログ出力して検証する。
3. 問題なければ `./raw_screenshots/` 内の残りすべての画像をバッチ処理し、`manifest.json` を生成して完了報告をする。
