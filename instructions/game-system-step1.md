# 指示書：ステップA（Part 1）データ設計＆P1/P2 6体エントリー画面の実装

あなたはレトロゲーム（ゲームボーイカラー・ポケットモンスター金銀世代）のUI/UXデザイナー兼フロントエンドエンジニアです。
スマホ向けWeb PvPバトルゲームの開発において、まずは**「データ基盤」と「バトル前の6体エントリー画面（仮登録UI）」**を React + CSS で実装してください。

※注意：バトル本編のロジックは次の指示書（Part 2）で実装します。今回は「P1とP2がそれぞれ6体のポケモンを選び終えて、バトル画面へデータを渡すところまで」を確実に動作させてください。

## 1. デザイン・共通スタイル要件（金銀風）

- **フォント：** Google Fonts の **`DotGothic16`** を全体適用。
- **ドット絵設定：** すべての画像に `image-rendering: pixelated;` を適用。
- **カラーパレット：** 背景 `#F8F8F8`、文字・枠線 `#181818`、強調色（P1：青 `#2860D8`、P2：赤 `#D82828`）。
- **ウィンドウ枠：** 白背景＋太めの黒枠（`4px solid #181818`）のレトロウィンドウデザイン。
- **レスポンシブ：** スマホ縦画面（最大幅 `420px`）を基準に中央配置。

## 2. マスターデータ設計（`src/data/pokemonMaster.js`）

既存のドット絵アセット（`output/assets/{ID}_front.png`, `{ID}_back.png`）を参照するテスト用ポケモンデータを作成してください。

- `output/manifest.json` に存在するポケモン（最大10体程度）をベースに、以下のスキーマでステータスを定義すること。
- もしアセットが足りない場合は、既存の `0383`（グラードン）や `0483`（ディアルガ）の画像を流用して最低6〜10体分のテストデータを用意すること。

```javascript
// データ構造の例
export const POKEMON_MASTER = [
  {
    id: "0383",
    name: "グラードン",
    type: "じめん",
    maxHp: 180,
    atk: 110,
    def: 95,
    spd: 3, // すばやさ段階（1〜5の整数：フレンダの矢印数に相当）
    moveName: "だんがいのつるぎ",
    sprites: {
      front: "/assets/0383_front.png",
      back: "/assets/0383_back.png",
    },
  },
  // ... 他のポケモンデータ
];
```

## 3. アプリ全体の画面遷移（State管理）

`App.jsx` で以下のゲームフェーズ（`phase`）を管理する骨組みを作成してください。

1. `TITLE`：タイトル画面（「バトル スタート」ボタン）
2. `ENTRY_P1`：プレイヤー1の6体選択画面
3. `HANDOVER_TO_P2`：「P2に スマホを わたしてね！」の中継画面
4. `ENTRY_P2`：プレイヤー2の6体選択画面
5. `BATTLE`：バトル画面（Part 1時点では、P1/P2の選出結果6体ずつを確認表示する仮画面＋「タイトルへ戻る」ボタンでOK）

## 4. 6体エントリー画面の仕様（`ENTRY_P1` / `ENTRY_P2`）

将来のステップB（カメラOCR読み取り）に差し替えやすいよう、**独立したコンポーネント（`EntryScreen.jsx`）**として作成してください。

- **上部：選出スロット（6枠）**
  - 最初の3枠に **`先発`** ラベル、残りの3枠に **`控え`** ラベルを表示。
  - 選んだポケモンのドット絵（`front`）と名前が順番に入る。タップすると選択解除できる。
- **中部：テスト用ポケモン一覧（タップで追加）**
  - `POKEMON_MASTER` のポケモンをグリッド表示（ドット絵、名前、HP、すばやさ段階の矢印 `▲` 表示）。
  - タップすると空きスロットに追加される（※同じポケモンの重複選出もテスト用に許可してOK）。
  - お試しプレイを楽にするため、**「ランダムで6たい えらぶ」**ボタンも配置すること。
- **下部：決定ボタン**
  - 6体すべて埋まったら「これで けってい！」ボタンが有効になる。

## 5. 実行・確認手順

1. `src/data/pokemonMaster.js` および各画面コンポーネントを作成する。
2. ビルド・起動し、`TITLE` → `ENTRY_P1`（6体選択）→ `HANDOVER_TO_P2` → `ENTRY_P2`（6体選択）→ `BATTLE`（仮画面に両者の先発3体・控え3体が表示されること）の一連の流れがエラーなく動くことを確認して報告する。
