# 指示書：Step 2-3a すばやさ判定と先攻・後攻決定の実装

あなたはレトロゲーム（ゲームボーイカラー・ポケットモンスター金銀世代）のフロントエンドエンジニアです。
Step 2-2で実装した「P1選択 → 目隠し画面 → P2選択」の流れに続けて、**両者が選んだポケモンの「すばやさ（`spd`）」を比較し、先攻・後攻を決定する仕組み（同速の場合はランダム決定）**を `BattleScreen.jsx` / `BattleScreen.css` に実装してください。

※重要（スコープ制限）：
今回は**「すばやさ比較と先攻・後攻の決定および結果表示」のみ**を実装します。
ダメージ計算、HPバーの減少、クールタイム（おやすみ）、控えからの交代、斬撃エフェクトは**まだ実装しないでください**。

## 1. 追加・更新する状態（State）

`BattleScreen.jsx` に以下のStateを追加してください。

- `turnOrder`：先攻・後攻の判定結果を保持するオブジェクト（初期値 `null`）
  ```javascript
  // データ構造の例
  {
    first: 'P1',        // 'P1' または 'P2'
    second: 'P2',       // 'P2' または 'P1'
    isTie: false        // すばやさが同値（ランダム決定）だった場合は true
  }
  ```

## 2. 先攻・後攻の決定ロジック

P2がポケモンを選択したタイミングで、以下のロジック（純粋関数 `determineTurnOrder(p1Pokemon, p2Pokemon)` として切り出すことを推奨）を実行してください。

1. P1が選んだポケモンの `spd` と、P2が選んだポケモンの `spd` を取得する。
2. **比較ルール：**
   - `p1Pokemon.spd > p2Pokemon.spd` の場合：`first: 'P1'`, `second: 'P2'`, `isTie: false`
   - `p2Pokemon.spd > p1Pokemon.spd` の場合：`first: 'P2'`, `second: 'P1'`, `isTie: false`
   - `p1Pokemon.spd === p2Pokemon.spd`（同速）の場合：
     - `Math.random() < 0.5` で `'P1'` または `'P2'` をランダムに選び、`isTie: true` にする。
3. 判定結果を `turnOrder` に保存し、`turnPhase` を `'CONFIRM_SELECTION'`（または `'SPEED_RESULT'`）へ遷移させる。

## 3. UI表示要件（結果の可視化）

判定結果フェーズにおいて、どちらが先攻になったかを直感的に確認できるよう以下を表示してください。

- **バトルフィールド上のバッジ表示：**
  - 選択された2体の立ち絵（またはステータス枠）の近くに、それぞれ金銀風の小さなバッジを表示する。
  - 先攻側：`1st せんこう`（目立つ枠・強調表示）
  - 後攻側：`2nd こうこう`
- **メッセージウィンドウの表示：**
  - **すばやさに差がある場合：**
    `P1(▲4) vs P2(▲2)！ せんこうは [先攻プレイヤー] の [先攻ポケモン名]！`
  - **すばやさが同じ（同速ランダム）の場合：**
    `すばやさが おなじ(▲3)！ ランダムで せんこうは [先攻プレイヤー] の [先攻ポケモン名] に きまった！`
  - ※ `▲` の数は実際の `spd` 数値に合わせて表示すること。
- **コマンドパネル（動作確認用）：**
  - テストを繰り返しやすいよう、`もういちど えらぶ（リセット）` ボタンを表示する。
  - ボタンを押したら `p1SelectedIndex`, `p2SelectedIndex`, `turnOrder` をすべて `null` に戻し、`turnPhase` を `'SELECT_P1'` へ戻す。

## 4. 実行・確認手順

1. `src/BattleScreen.jsx` および `src/BattleScreen.css` を更新する。
2. ビルド・起動し、以下の3パターンがすべて正しく動作することを検証して完了報告を行うこと。
   - P1の `spd` が高いとき、確実にP1が `1st せんこう` になること。
   - P2の `spd` が高いとき、確実にP2が `1st せんこう` になること。
   - P1とP2の `spd` が同じとき、`isTie` 用のメッセージが表示され、リセットして複数回試すとP1とP2がランダムに先攻になること。
